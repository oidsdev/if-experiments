How scoring works

The total is the average of clarity, examples, and safety, rounded to the nearest whole number. The same text always gets the same score.

  • Clarity. A description of what the skill does and when to use it, at least three headings, an Examples section, and three numbered steps.
  • Examples. Two or more fenced code blocks, written out in full, with a language tag on the fence.
  • Safety. A warning about secrets, credentials, or API keys, near those words. No hardcoded keys. Every skill gets this check.
Point values
  • Description, 40. 80 characters or more scores 40. 40 to 79 scores 25. 12 to 39 scores 10. Counted from the YAML description or the opening paragraph, whichever is longer.
  • Sections, 30. Three ## or ### headings score 30. Two score 20. One scores 10. Headings inside code fences do not count.
  • Concrete detail, 30. An Examples heading scores 15. Otherwise "for example", "e.g.", or "example:" scores 10. Three numbered steps score 15. One or two steps score 5.
  • Code blocks, 50. Two fenced blocks score 50. One scores 30.
  • Copy-pasteable, 50. Every block needs real text, not a placeholder such as YOUR_KEY, changeme, or a line of dots. At least one fence needs a language tag. Some complete blocks score 25. All complete, but none tagged, scores 40.
  • Secrets warning, 50. The text has to name a secret, credential, API key, password, private key, access token, or .env, with never, do not, avoid, must not, should not, or warning within 400 characters. The noun alone scores 10. Both, farther apart, scores 25.
  • No hardcoded keys, 50. A known key shape, or a long quoted assignment to a secret-like name, scores 0. Obvious fakes (example, placeholder, changeme, sample) are ignored. The page does not print the key back.

The one-line note under each category is the gap worth the most points. Surrounding whitespace is ignored, and Windows and Unix line endings score the same.
